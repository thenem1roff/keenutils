# Flowseal → nfqws2: разработка модуля KeenUtils (пункт 77)

## Состояние: этап 1 (безопасная конвертация и хранение)

В основном `install` добавлено только подключение отдельного модуля по пункту **77**,
а также строго опциональный режим для тестирования файла `install` из другой ветки.
После выбора `0` в модуле происходит возврат в главное меню KeenUtils через
обычный возврат из дочернего процесса (без `exec` основного установщика).

Сейчас доступны:
- загрузка последнего опубликованного ZIP-релиза Flowseal (а не изменяющегося `main`);
- отображение `general*.bat`, выбор стратегии и подтверждение `[Y/n]`;
- вопрос об игровых TCP/UDP-портах, где Enter = **Да**;
- конвертация через исходный MIT-движок Sxlenium и автоматическое сохранение;
- список сохранённых стратегий с названием и номером выпуска Flowseal;
- просмотр конфигурации и отчёта, удаление сохранённой стратегии по `[Y/n]`;
- повторная конвертация с переносом предыдущей копии в `history/`.

**Пока не реализовано:** использование штатных LIST/BIN nfqws2 вместо Flowseal,
применение к рабочему `nfqws2.conf`, проверка реального запуска, откат после
применения и интеграция с меню удаления KeenUtils (88). На первом этапе это
намеренно **невозможно**: ни одна ветка программы не пишет в
`/opt/etc/nfqws2/` и не перезапускает службу.

## Локальное хранение

Обычный режим:
- `/opt/bin/keenutils-flowseal`: загрузчик модуля, сохраняется после первого запуска;
- `/opt/etc/keenutils/flowseal/current.version`: установленная версия;
- `/opt/etc/keenutils/flowseal/runtime/<версия>/`: код и MIT-лицензия;
- `/opt/etc/keenutils/flowseal/strategies/flowseal-<версия>-<название>/`: результат;
- `/opt/etc/keenutils/flowseal/history/`: старые редакции после пересоздания;
- `/opt/etc/keenutils/flowseal/tmp/`: временные распаковки, удаляются автоматически.

Для тестового запуска из ветки применяются отдельные пути:
`/opt/bin/keenutils-flowseal-dev` и `/opt/etc/keenutils/flowseal-dev/`.
Это предотвращает замену стабильной копии и смешивание хранилищ.

В папке каждой сохранённой стратегии находятся `nfqws2.conf`,
`info.json`, `report.json`, `REPORT.md` и требуемые файлы из результата
конвертации. `info.json` хранит название, номер выпуска, имя .bat,
состояние игровых портов, SHA256 исходного профиля, SHA256 ZIP и дату.

## Как тестировать из install, не заменяя рабочий utils

Сначала установите обычный KeenUtils и nfqws2 через штатные процедуры,
если они ещё не установлены. Для первого этапа nfqws2 не является
обязательным: к его файлам конвертер пока не обращается для записи.

Скачайте **именно версию install из тестовой ветки**:

```sh
wget -O /tmp/keenutils-flowseal-dev-install.sh \
  https://raw.githubusercontent.com/thenem1roff/keenutils/feature/flowseal-converter-77/install
```

Запустите её **через shell Entware от root**, без установки поверх `utils`:

```sh
KEENUTILS_DISABLE_UPDATE_CHECK=1 \
KEENUTILS_FLOWSEAL_DEV_MODE=1 \
KEENUTILS_FLOWSEAL_REF=feature/flowseal-converter-77 \
sh /tmp/keenutils-flowseal-dev-install.sh
```

Теперь откройте **77** → **1** → выберите стратегию → подтвердите конвертацию,
далее **2** для просмотра. Нажатие `0` в модуле возвращает в тот же
тестовый `install`. Нажатие `00` в главном меню завершает программу.

Установленная команда `utils` в этот момент **не меняется**. Поэтому запуск
обычного `utils` до слияния тестовой ветки не показывает новый пункт 77.

### Обновления

При каждом **входе в пункт 77** загрузчик запрашивает только
`flowseal.version` из выбранной ветки и сравнивает его с локальным
`current.version`. Если они совпали, весь код работает локально и **не**
скачивается повторно. При отличии скачиваются новые файлы в отдельный
временный каталог, проверяется синтаксис shell/Python и затем атомарно
переключается версия. В случае проблем с GitHub используется сохранённая
копия, если она уже есть.

**Важно разработчику:** после каждого изменения `flowseal_converter`,
`manager.py` или vendored-модулей нужно увеличить `flowseal.version`,
иначе загрузчик по дизайну продолжит использовать локальную копию.

ZIP Flowseal скачивается только при выборе **«Добавить стратегию»**;
после завершения операции временная распаковка удаляется. Сохранённые
конфигурации при обновлении модуля не удаляются.

## Автоматические тесты

```sh
sh -n install flowseal_converter
python3 -m unittest discover -s tests -p test_flowseal_manager.py -v
```

В GitHub Actions также работает shell-проверка возврата из отдельного
модуля в главное меню. Тесты конвертации используют небольшой локальный
ZIP-макет и не требуют ни сетевого доступа, ни реального роутера.
