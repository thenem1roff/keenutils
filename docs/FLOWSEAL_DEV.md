# Конвертер Flowseal → nfqws2 для KeenUtils (пункт 77)

## Текущий этап: Shell + AWK, конвертация, установка и откат

Код конвертера работает через POSIX sh, AWK и Lua-совместимость. **Python на роутер
не загружается и не устанавливается.** Оригинальный конвертер на Python хранится
исключительно в tests/reference/ для сравнительных тестов GitHub Actions.

Пункт 77 в основном install запускает отдельный локально установленный модуль.
Пункт 0 внутри модуля возвращает в **тот же** главный экран KeenUtils.

Доступно:
- Получение списка профилей general*.bat из дерева тега последнего официального релиза Flowseal, без архива
- Выбор ALT / FAKE / EXP и других стратегий, подтверждения [Y/n] с ответом Y по Enter
- Игровые порты TCP/UDP с ответом Y по Enter
- Парсинг winws-аргументов, fake, hostfakesplit, multisplit, multidisorder,
  fakedsplit, fakeddisorder, syndata и нескольких последовательных правил
- Lua-функция для hostfakesplit altorder=1 из оригинального MIT-конвертера
- Сопоставление базовых списков Flowseal со штатными списками nfqws2:
  list-general → user.list; list-exclude → exclude.list;
  ipset-all → ipset.list; ipset-exclude → ipset_exclude.list
- Дополнительные списки (например, list-google) и бинарные шаблоны сохраняются
  **отдельно** в каталоге результата с названием стратегии и версии
  в имени файлов (без записи в системные файлы)
- Автоматическое сохранение стратегии с названием и номером версии Flowseal
- Просмотр отчётов, конфигурации, проверки совместимости и сравнения с рабочей
- Применение выбранной стратегии, переключение между сохранёнными стратегиями,
  резервные копии и откат
- Удаление стратегии с защитой активной
- В меню сохранённой стратегии выбранный отчёт/конфигурация/проверка показывается
  **ниже меню**. Enter закрывает просмотр и возвращает к чистому подменю;
  возврат на предыдущий уровень — через `0`
- Пересоздание стратегии с переносом предыдущей редакции в history/

**Применение доступно только по отдельному явному подтверждению `APPLY`.**
Конвертер может менять работающую конфигурацию и перезапускать nfqws2,
поэтому тестировать сначала на отдельном Entware. Основная ветка KeenUtils
остаётся неизменённой до завершения тестов.

При применении сначала создаётся резервная копия конфигурации и журнал новых
ресурсов, затем только недостающие BIN/LIST перемещаются в системные каталоги.
Если системный файл уже есть и содержимое отличается, применение отменяется
(ничего не перезаписывается). Текущие параметры ISP_INTERFACE, POLICY_NAME,
POLICY_EXCLUDE, NFQUEUE_NUM, USER, IPV6_ENABLED и логирования сохраняются.
Затем nfqws2 запускается или перезапускается, после чего проверяется статус.
При ошибке запуска конвертер автоматически пытается восстановить предыдущую
конфигурацию, удалить только неизменённые новые файлы и вернуть состояние службы.
Резервные копии сохраняются в `deployments/backups`. Ручной откат
подтверждается вводом `ROLLBACK`. Можно последовательно откатить несколько
применений, если все резервные копии доступны.

**Необходимая дополнительная проверка:** автоматический откат при сбое процесса
не гарантирует восстановление после внезапной потери питания или `SIGKILL`.
В таком случае копии остаются, но требуется ручное восстановление.
Статус службы подтверждает запуск демона, **не подтверждает** эффективность
обхода блокировок и доступность всех сайтов. Гибридный режим пока не включён:
он требует отдельной проверки комбинирования стратегий, чтобы не нарушить
уже настроенные списки и очереди.

Конвертация по синтаксису не гарантирует эффективности стратегии у конкретного
провайдера. Совместимость с актуальным nfqws2 надо проверять отдельно.

## Папки и файлы

- /opt/bin/keenutils-flowseal — локальный загрузчик обычной версии
- /opt/etc/keenutils/flowseal/current.version — версия установленного модуля
- /opt/etc/keenutils/flowseal/runtime/<версия>/ — Shell + AWK + Lua + MIT
- /opt/etc/keenutils/flowseal/strategies/ — автоматически сохранённые результаты
- /opt/etc/keenutils/flowseal/history/ — предыдущие редакции пересозданных стратегий
- /opt/etc/keenutils/flowseal/tmp/ — временные BAT/BIN/LIST, очищаются после операции

Папка стратегии содержит nfqws2.conf, info.json, stats.txt, REPORT.md,
а также подкаталоги lists/ и blobs/ для необходимых дополнительных файлов.

В тестовом режиме используется отдельное хранилище:
- /opt/bin/keenutils-flowseal-dev
- /opt/etc/keenutils/flowseal-dev/

Стабильная копия от тестов не заменяется.

## Тестировать через install без замены команды utils

Скачайте install из отдельной ветки разработки:

~~~sh
wget -O /tmp/keenutils-flowseal-dev-install.sh \
  https://raw.githubusercontent.com/thenem1roff/keenutils/feature/flowseal-converter-77/install
~~~

Запустите от root в Entware:

~~~sh
KEENUTILS_DISABLE_UPDATE_CHECK=1 \
KEENUTILS_FLOWSEAL_DEV_MODE=1 \
KEENUTILS_FLOWSEAL_REF=feature/flowseal-converter-77 \
sh /tmp/keenutils-flowseal-dev-install.sh
~~~

Затем выберите **77 → 1**, выберите стратегию и игровые порты. После
конвертации результат автоматически окажется в **77 → 2**. Нажатие 0
возвращает сначала в подменю, затем из модуля в тестовый install. Обычная
команда utils по-прежнему запускает основную установленную версию.

При первом импорте может понадобиться пакет Entware `jq` (программа
предложит его установить). `awk` и остальные базовые инструменты обычно уже
входят в BusyBox. `unzip`, Python и расширенный `od` не требуются. Lua-совместимость
поставляется заранее закодированным файлом `hostfakesplit_alt1.hex`, поэтому
ограничения BusyBox `od` (`-An -tx1 -v`) не влияют на конвертацию.

## Как обновляется модуль

При входе в 77 запрашивается небольшой файл flowseal.version. Если он не
изменился, исполняется локальная версия из runtime/. Если версия изменилась,
код загружается в отдельный каталог, проверяется и только после успешной
подготовки активируется. При недоступности GitHub ранее установленный модуль
остаётся доступен.

В **режиме разработки** install может повторно загрузить только небольшой
файл начального загрузчика — это нужно для миграции со старого Python-прототипа.
Сам код Shell + AWK повторно не скачивается при совпадающей версии.

Список профилей Flowseal получается по API GitHub для тега последнего релиза.
После выбора стратегия и только нужные ей BIN/LIST скачиваются по тому же тегу.
Временные скачанные файлы удаляются после операции; полный архив не требуется. Сохранённые стратегии
переживают обновления модуля.

**Разработчику:** при изменении flowseal_converter, menu.sh, converter.awk,
deployer.sh, validator.sh или Lua-функции увеличивайте flowseal.version.

## Автоматические проверки

Без Python:

~~~sh
sh -n install && sh -n flowseal_converter && sh -n modules/flowseal/menu.sh
sh -n modules/flowseal/validator.sh && sh -n modules/flowseal/deployer.sh
sh tests/flowseal-converter-regressions.sh
sh tests/flowseal-import-regressions.sh
sh tests/flowseal-deployer-regressions.sh
~~~

В GitHub Actions отдельно выполняются сравнительные тесты Shell/AWK
против исходного конвертера Python на зафиксированных оригинальных .bat
Flowseal. **Этот Python нужен только тестовому окружению GitHub, не Keenetic.**
Есть также проверка возврата из пункта 77 в главное меню.

## Почему не используется ZIP

На BusyBox 1.37.0 утилита `unzip` может не поддерживать `-Z1`, поэтому
модуль больше не вызывает `unzip`. Он получает:
1. номер выпуска из `/releases/latest` GitHub API;
2. список `general*.bat` из `/git/trees/<версия>?recursive=1`;
3. только выбранный `.bat`, а затем необходимые BIN/LIST из `raw.githubusercontent.com`
   для **того же тега**.

Номер версии и SHA дерева выпуска сохраняются в `info.json`. Это позволяет
отличать разные версии Flowseal, даже если их основная ветка изменилась.
Передача данных по тегу не означает полной криптографической фиксации
отдельных файлов — для более строгой проверки в будущем можно проверять
Git blob SHA каждого скачанного файла.

## Меню установки и отката

В `77 → 2 → выбранная стратегия`: пункты проверки совместимости, сравнения,
применения (требуется строка `APPLY`) и удаления.

В `77 → 3`: статус службы, резервные копии и откат (строка `ROLLBACK`).

В тестовом режиме `flowseal-dev` хранилище и код отделены от стабильного
KeenUtils, **но применение изменяет конфигурацию именно того Entware, из
которого запущен пункт 77**. Используйте отдельный тестовый Entware.

## Проверка релиз-кандидата на отдельном Entware

1. Проверить, что пакет `nfqws2-keenetic` установлен, существуют
   `/opt/etc/init.d/S51nfqws2`, `/opt/usr/bin/nfqws2` и стандартные
   каталоги `/opt/etc/nfqws2/lua`, `blobs`, `lists`.
2. В пункте 77 выбрать и сконвертировать ALT12 или ALT13.
3. Открыть **77 → 2 → профиль → 3** (проверка), затем **4** (сравнение).
   Ресурсы, отличающиеся от уже существующих, блокируют применение.
4. Выбрать **5 — Применить** и ввести `APPLY`.
   Проверить состояние службы, доступность нужных сайтов и новый конфиг.
5. Сконвертировать другой профиль, применить его, затем проверить
   **77 → 3 → 3 — Восстановление** (ввод `ROLLBACK`).
6. Повторить откат, чтобы восстановить конфигурацию до первого применения.
   При необходимости проверить сохранённые файлы в `deployments/backups`.

Дополнительные проверки перед слиянием в `main`: разные релизы Flowseal,
реальное поведение nfqws2, влияние политики Keenetic, длительный запуск и
фактическая доступность сайтов. Объединение двух разных наборов правил в
один гибрид намеренно оставлено отдельной задачей: у него могут быть
конфликтующие имена Lua blob-файлов и порядок профилей.
